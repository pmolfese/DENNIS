The Decomposition Bench

Instead of one fixed temporal → spatial pipeline, the PCA tab becomes a bench: drag a decomposition off the shelf, point it at raw data or at any earlier step, expand it to run the scree test, then set the factor count and solve. Drag the cards, wire the ports, expand the headers — this mockup is live.

Why a bench

The current tab hard-codes one order: temporal scree, temporal PCA, spatial scree, spatial PCA. That is the Möcks/Dien default, but it is only one route. A bench lets the same group feed a spatial-first decomposition, an Infomax run, and the classic dual pipeline side by side, and keeps all three results in AnalysisStore under one group.

Every card is one doPCA

A card is a thin wrapper over what already exists: matrix type (COV/COR/SCP), decomposition (SVD/NIPALS), loading (Kaiser/None/Cov/Cureton–Mulaik), rotation, factor count. The card's mode — temporal, spatial, frequency — is the PCAMode that decides which way the EPTensor is unfolded before the call.

Input is the graph edge

Each card names its input: the raw group tensor, or the residual/score matrix of an upstream card. Wiring a spatial card to a temporal card's output reconstructs today's TwoStepPCA exactly — the two-step run becomes a saved template rather than a special code path.

Scree lives in the card

Expanding a card runs parallel analysis on whatever that card's input actually is, so the noise floor is right for the second step too. Click a bar to set the retained count; the card goes stale until you solve again.

Open questions

  • Do downstream cards consume scores, residuals, or the reconstructed tensor? Probably a picker on the edge.
  • Fan-out is easy; fan-in (two inputs) only makes sense for compare/plot cards.
  • Cache invalidation: editing a card should mark everything downstream stale, not silently reuse.
  • Saved benches as JSON — the "recipe" a paper's methods section can cite.
